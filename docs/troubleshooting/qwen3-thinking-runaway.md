# qwen3 thinking 폭주 — /rewrite가 항상 5초 타임아웃

> 2026-08-24, .164 실기동 스모크에서 발견. 단위 테스트(mock)로는 잡을 수 없는 유형.

## 증상

- 모델이 GPU에 정상 로드(100% GPU, 64 tok/s)됐는데 `/rewrite`가 **매번 정확히 5초에서 503(upstream_timeout)**.
- 웜업을 해도 동일. GPU 사용률은 98%로 계속 바쁨.

## 원인 (워크플로우)

```
wrapper ──/api/chat (프롬프트에 "/no_think" 포함, format=JSON스키마)──▶ ollama
                                                                        │
        Qwen3 원래 문법의 "/no_think"(생각 끄기 스위치)를               │
        ollama의 qwen3 챗 템플릿은 그냥 일반 텍스트로 취급 ─────────────┤
                                                                        ▼
        thinking(속으로 생각하는 출력)이 계속 생성됨
        + JSON 스키마 강제(format)와 얽혀 종결 조건에 도달하지 못함
        → 31,000+ 토큰 폭주 생성 (4096 컨텍스트를 넘겨 context shift까지 발생)
```

이걸 키운 두 번째 구멍:

```
wrapper가 5초에 연결을 끊음 ──✂──▶ ollama는 서버 쪽 생성을 멈추지 않음
                                    (stream=false라 연결 끊김 감지도 늦음)
→ GPU가 폭주 작업에 계속 잡혀 있어 다음 요청들도 연쇄 타임아웃
```

## 수정 (2겹)

`wrapper/src/app/usecase/rewrite.py` — 커밋 63ed56b:

```diff
             "stream": False,
+            "think": False,            # ← 근본 원인 제거: ollama의 공식 생각-끄기 방법은
+                                       #    프롬프트 문자열이 아니라 API 필드다
             "format": schema,
-            "options": {"temperature": 0},
+            "options": {"temperature": 0, "num_predict": 512},
+                                       # ← 가드레일: 생성 토큰 상한. 클라이언트가 끊어도
+                                       #    서버가 계속 돈다는 걸 실측했으므로, 폭주 자체를
+                                       #    불가능하게 만드는 유일한 방어선
```

프롬프트의 `/no_think` 문자열은 제거(효과 없는 주술이므로).

## 결과

| | 수정 전 | 수정 후 |
|---|---|---|
| 콜드(모델 로드 포함) | 5s 타임아웃 | 3.56s 성공 |
| 웜 | 5s 타임아웃(폭주) | **1.33s 성공** |

## 교훈

1. **모델 제어는 그 서빙 런타임의 공식 API로** — 모델 카드의 프롬프트 문법이 런타임 템플릿에서 동작한다고 가정하지 말 것.
2. **클라이언트 타임아웃은 서버 자원을 보호하지 않는다** — 생성 상한(num_predict) 같은 서버측 상한이 반드시 따로 있어야 한다.
3. 이런 결함은 mock 테스트가 못 잡는다 — **실기동 스모크를 머지 조건에 넣은 것이 유효**했다.
